# London instrument list captures

- Captured on 2026-09-16 with a plain GET (user agent `Equibles/1.0`, no cookies) of `https://docs.londonstockexchange.com/sites/default/files/reports/Instrument%20list_81.xlsx`, edition 81, 8,675,815 bytes, `Last-Modified: Thu, 13 Aug 2026 13:14:12 GMT`, served as `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`. The exchange's own reports page is a script application that never states this address, so the edition number is found by asking this host which numbers exist; 82 and higher answered 404 that day.
- `instrument-list.trimmed.xlsx` keeps the workbook's `1.1 Shares` sheet alone, its preamble and header rows verbatim and 18 of the 1,559 share rows, each cell exactly as the file states it. Two edits were unavoidable: the shared-string table is compacted to the strings these rows use, and the sheet's own `Number of Instruments:` line is restated as 18 so the file still counts itself correctly. The other thirteen sheets, the styles and the images are dropped.
- The kept rows cover what the adapter has to decide: a main-market line (III), an AIM line (4BB), the specialist fund segment (AOF, TORG, TORO), admission to trading only (GPM), the share-class dot (BT.A) and the padded mnemonic (RR.), the five currencies the file uses (GBX, GBP on 44GL, USD on BPCR, EUR on AERI, JPY on KNM), a share whose EEA home is another venue (AZN), two currency pairs of one security (AERI/AERS, BPCP/BPCR, TORG/TORO) and one register triple quoted only in dollars (DFI/DFIB/DFIJ).
- `instrument-list.count-mismatch.derived.xlsx` is that file with the stated count raised to 19, the shape a truncated download takes.
- `instrument-list.no-shares-sheet.derived.xlsx` renames the sheet to `1.0 All Equity`, the shape a re-organised workbook takes.
- `instrument-list.two-sterling-lines.derived.xlsx` repoints BPCR's currency cell to the file's own `GBP` string, so that security holds a pence line and a pound line and names no single primary one.
- `instrument-list.symbol-collision.derived.xlsx` repoints AOF's mnemonic cell to the file's own `RR.` string, so two securities on one venue write the same symbol once the padding is dropped.
